# DouK-Manager V0.1.7 使用手册

> 文档状态：V0.1.7 本地候选手册，按当前程序界面和实现编写。
> 本手册不代表最终发布已经完成。版本身份已统一为 `0.1.7`，完整隔离回归和源码候选前台版本确认已经通过；正式包验证及版本级 E 尚未执行。

本手册使用 `<管理器目录>`、`<下载引擎目录>`、`<视频账号目录>`、`<索引目录>` 和合成 A/W 编号说明操作。不要把正式主页地址、账号身份、Cookie、Token、原始日志或正式路径写入截图、问题报告或诊断文本。

## 1. 程序定位、组件关系与数据流

### 设计目的

DouK-Manager 是 Windows 便携式管理程序。它统一协调账号采集、正式账号主档、任务模板、下载引擎、结果日志、截图归档、快捷方式索引、观察名单、备份和诊断，但不替代下载引擎本身。

核心数据流如下：

```text
浏览器油猴脚本
  -> 本机账号采集服务
  -> 正式 settings_master.json + 正式 Excel

浏览器油猴脚本“加入观察”
  -> 本机 /watchlist/observe 服务
  -> Data/watchlist*.json
  -> 用户确认转正
  -> 正式 settings_master.json + 正式 Excel

settings_master.json
  -> 账号任务/批次任务模板
  -> 唯一正式 settings.json
  -> 下载引擎 main.exe
  -> 原生日志
  -> DownloadTask 任务日志
  -> 下载结果/结果看板/账号审计/日志统计
```

### 使用前提

- 同一时间只运行一个管理器实例和一个受管理下载引擎进程。
- 下载引擎目录中必须存在 `main.exe`，其 `_internal/Volume` 是唯一正式 Volume。
- 正式写入前必须等总览显示启动状态 `READY`。
- `DEGRADED_READ_ONLY` 是保护状态，不是可忽略的警告。

### 数据影响、风险与恢复

只读页面不会主动更改业务数据。任务激活、账号采集、观察记录变更、审计决定、引擎更新和恢复会写入各自受控文件，并通过锁、备份、原子替换和复读校验保护。操作失败时先保留现场和界面中的固定错误，再按本手册对应章节恢复，不要手工拼接 JSON、移动 `Volume` 或盲目重复正式写入。

## 2. 安装、升级、替换与版本身份

### 设计目的与使用前提

便携版应与运行数据、正式下载引擎分开判断版本身份。替换管理器程序不能代替正式数据备份，回退程序也不能撤销新版本已经产生的业务写入。

### 首次安装

1. 取得受信任的 Windows X64 ZIP 及配套 SHA-256 文件。
2. 先核对 ZIP 的 SHA-256，再解压到一个全新的 `<管理器目录>`。
3. 打开包内 `BUILD-INFO.txt`，核对产品名、`Version`、`Commit` 和构建时间。
4. 确认下载引擎、视频账号目录和索引目录后启动管理器。
5. 在总览等待启动检查结束；只有 `READY` 才继续正式写入或运行任务。

### 升级或替换

1. 停止下载队列、后台监听和账号采集服务，正常关闭旧管理器。
2. 保留旧 `<管理器目录>` 作为可恢复副本；不要覆盖其中的 `Data`、`Logs`、`Backups` 或 `Updates`。
3. 需要保护完整正式 Volume 时，先在旧版总览执行“手动完整备份 Volume（大文件）”。
4. 把新包解压到新目录，核对 ZIP 哈希和 `BUILD-INFO.txt` 后再启动。
5. 在“设置”页重新确认正式路径，并等待重新检查返回 `READY`。

### 当前候选边界

当前源码包版本、运行时版本、Windows `BUILD-INFO.txt` 模板和 Artifact 名称均已统一为 `0.1.7`。
这只完成版本身份收口，不等于正式发布：当前身份候选的完整隔离回归与普通 Windows 前台版本确认已通过，
但没有生成或验收正式安装包，版本级 E 仍须单独授权和执行。
任何缺少 `BUILD-INFO.txt`、显示其他版本或提交身份不符的构建，都不能作为正式 V0.1.7 发布包验收通过。

### 失败与恢复

- 哈希不匹配：停止解压或运行，重新取得受信任产物。
- `BUILD-INFO.txt` 缺失或版本/提交不符：不要覆盖旧目录，也不要称为 V0.1.7 正式包。
- 新版启动失败：保留新目录和日志，关闭所有相关进程后回到旧管理器目录。业务数据是否需要恢复必须按备份时间单独判断。
- 不要同时运行新旧版本，也不要用程序目录回退替代数据库或主档恢复。

## 3. 启动安全检查、总览与安全关闭

### 设计目的

启动流程先确认路径、唯一 Volume、关键文件、进程状态、实例锁、观察控制状态和 Startup 快照，再开放写入。总览同时提供最近一次可用任务结果、运行状态和观察提醒。

### 操作步骤

1. 启动后先查看总览顶部状态。常见阶段为 `BOOTSTRAPPING`、`SAFETY_CHECKING`、`READY`、`DEGRADED_READ_ONLY` 和 `CLOSING`。
2. `READY` 时可使用任务、采集、观察写入、审计和引擎维护功能。
3. 失败时点击“展开诊断”，查看“启动安全状态”和“正式数据与服务状态”。
4. 可用“复制错误”取得安全诊断，或用“打开管理器日志”查看本次管理器日志。
5. 修正路径或恢复数据后点击“重新检查”。不要靠重启反复碰运气。
6. 用“刷新状态”更新轻量运行状态；该按钮不会启动任务。
7. 正常退出时关闭主窗口。若后台工作仍在取消或收尾，等待窗口自行完成关闭。

### 总览口径

- 统计卡、结果构成、处理效率和异常均绑定当前最近一次可用任务快照，不是实时下载速度。
- “有新作品”按账号处理次数统计，不是作品文件数量。
- 平均效率按实际开始账号数和任务总用时计算；总用时可包含等待、暂停和结果查看时间。
- 失败或用户停止的任务也可能有可用汇总；退出码 0 不等于每个账号都成功。
- 近 7 天趋势按任务结束的本地日期聚合账号处理次数，同一账号多次运行会重复计次。
- 新任务运行时可继续显示上一次可用结果；日志不完整、不可解析或已变化时会显示未知、部分证据或需刷新。

### 数据影响、风险与恢复

路径、进程和正式数据校验通过后，启动流程会在进入 `READY` 前于 `<管理器目录>/Backups/Startup` 创建受控快照。首次启用观察功能时，只有启动前捕获到可信首次启用/兼容配置证据才会初始化三个观察 Data 文件；初始化或快照失败会保持只读保护。总览结果读取任务日志；“手动完整备份 Volume（大文件）”会复制整个正式 Volume，可能占用大量空间。关闭被拒绝时不要强制终止进程；先让关键写入、采集停止或下载汇总到达终态，再次正常关闭。

## 4. 路径与安全设置

### 设计目的与使用前提

“设置”页统一保存下载引擎、视频目录、索引目录、旧截图迁移目录，以及默认的批次数、暂停秒数和后处理选项。正式 Volume 始终由 `main.exe` 所在目录推导，不能单独指向另一份数据库或主档。

### 操作步骤

1. 在左侧导航打开“设置”。
2. 选择或填写“下载引擎 main.exe”“视频账号目录”“索引目录”和“旧截图目录（仅迁移）”。
3. 只修复路径时点击“仅保存正式路径并重新检查”。
4. 同时修改每批账号数、暂停秒数和默认后处理时，点击“保存全部设置并重新验证正式数据”。
5. 等待总览重新检查完成并返回 `READY`。

### 数据影响与风险

设置写入 `<管理器目录>/Data/app_config.json`。保存路径后会重建管理路径对象并重新执行启动检查；不会搬运旧目录的数据。兼容下载引擎会读取每批账号数和暂停秒数，旧引擎可能继续使用自身默认值。

### 失败与恢复

- 路径不存在、Volume 不完整或进程探测不确定时会进入只读保护。
- 修正为原路径后再次点击路径保存，等待 `READY`。
- 不要同时保留两份“正式 Volume”并在设置中来回切换，也不要在引擎或采集服务运行时改路径。
- 设置文件损坏时应从旧管理器目录或已验证副本恢复；不要据猜测重建正式路径。

## 5. 主题、窗口与界面导航

### 设计目的

浅色、深色和跟随系统只改变显示，不改变账号、任务、下载配置或后台状态。窗口布局支持普通、最大化和高 DPI 缩放，左侧导航在紧凑宽度会折叠。当前自用部署基线固定为 27 英寸 2560×1440 显示器和 Windows 100% 缩放；多缩放实机发布验收已取消，但程序原有响应式和高 DPI 兼容能力继续保留。

### 操作步骤

1. 在“设置”的“外观”中选择“跟随系统”“浅色”或“深色”。选择后立即应用并保存。
2. 右上角太阳/月亮按钮切换为当前外观的相反固定主题。
3. 要恢复自动跟随，回到“设置”重新选择“跟随系统”。
4. 顶部搜索框当前只按页面或功能名称定位总览、下载队列、结果看板等入口，不搜索账号或任务。
5. 正常关闭后会保存窗口普通尺寸、位置和最大化状态；屏幕配置变化或记录损坏时会回到当前屏幕安全范围。

### 数据影响与风险

主题策略键为 `ui/theme/strategy`。指定隔离 home 或 UI 状态文件时，设置保存在该隔离位置，例如 `<管理器目录>/Data/UI/window_state.ini`；未指定时使用当前 Windows 用户范围的 `loner913/DouK-Manager-UI` INI 设置，而不是管理器 `Data`。主题切换不保存页面内未提交表单，也不承诺重启后回到上次页面。

### 失败与恢复

- “主题已应用，但偏好保存失败”表示当前显示已变化，但重启后可能丢失选择；处理 UI 配置写入问题后重新选择。
- 系统主题无法识别时，“跟随系统”的实际外观回退浅色，但保存策略仍是 `system`。
- 缩放后若控件不可达，先最大化或增大窗口并记录屏幕缩放；不要把文件选择框或外部浏览器样式当作管理器主题缺陷。

## 6. 油猴脚本、账号采集器与正式 Excel

### 设计目的与使用前提

正式采集把同一个新账号事务性追加到 `settings_master.json` 和正式 Excel。浏览器脚本只调用本机服务，不直接写文件。账号昵称和抖音号必须识别完整，当前页面必须可见。

### 首次设置与正式采集

1. 在“账号采集”页按需执行一次“迁移旧Excel/分类/截图”。该操作复制旧资料，源文件不删除，`settings_master.json` 不从旧采集器复制。
2. 点击“导出油猴脚本”，在油猴扩展中安装导出的脚本。
3. 点击“启动采集服务”，等界面报告健康检查通过。
4. 在浏览器打开要采集的账号主页，确认脚本面板已识别昵称、抖音号、mark 和只读主页字段。
5. 需要时点击“重新识别”；预检通过后点击“同时添加 JSON + Excel”。
6. 只有界面明确显示双文件写入和复读成功后，才把本次正式采集视为完成。
7. 完成采集后回到管理器点击“停止采集服务”。

### 数据影响与风险

正式采集会追加主档数组和 Excel 尾部行，更新即时 `.bak`，并按既有周期保留历史快照；成功后可保存账号截图。旧 Excel 既有行原样保留，只补齐尾部缺失行。分类和截图动作有各自写入范围，不能用一项成功推断另一项成功。

### 当前观察入口边界

本机采集服务提供受会话保护的 `/watchlist/observe` 观察接口，当前候选 v2.4.9 油猴脚本也提供“加入观察”按钮。按钮只在当前可见主页已识别完整昵称/抖音号且没有其他写入动作时启用。填写窗口允许编辑观察名称、选择原因、填写备注和选择 7/15/30/45/90 天或自定义日期和时间；前五个选项均按提交时刻相对计算，自定义项必须同时选择日期和具体时间。至少选择一个原因，选择“其他”时备注必填。脚本只提交观察意图，不直接写 JSON、Excel 或正式主档；服务返回的结构化结果只显示 W/A 编号和状态，不回显完整 URL。

观察请求单次超时 3 秒，连接错误、超时和暂时性 5xx 最多自动重试 3 次；每次重试复用同一个 `request_id` 和完整 payload。`READ_ONLY`、`RECOVERY_REQUIRED`、校验、重复和权限类结果不自动重试。超时只表示结果尚未确认，先在管理器观察名单中核对，不要立即重复提交。当前候选的“加入观察”入口已经在本机默认浏览器和隔离合成数据中完成前台验收；正式使用时仍须先启动当前管理器的采集服务，不要手工拼请求、手工创建观察 JSON，或把正式按钮当作观察按钮。

### 失败与恢复

- 脚本未连接：确认管理器采集服务已启动，再点击“重新识别”。
- 预检失败：界面会明确本次未写 JSON/Excel；修正识别或重复问题后再预检。
- 提交超时或结果不确定：先检查管理器采集日志及双文件一致性，不要立刻重复点击。
- 双文件不一致：停止正式采集，保留备份和错误，按事务恢复处理。
- 管理器退出后旧采集进程不能继续获得新的观察写入授权；重新启动后必须重新通过 Startup。

## 7. settings_master.json、A 编号与不可重排原则

### 设计目的

`settings_master.json` 是正式账号主档。A 编号是 `accounts_urls` 数组的一基位置：数组第一个对象是 A1。空主页、停用账号或任务筛选都不能让后续账号重新编号。

### 使用规则

- Excel 用于正式采集配套记录，不是点击“打开主页”时的 URL 权威来源。
- 主档 `enable=false` 表示正式账号永久停用，不表示观察状态。
- 任务模板只选择账号；它不能改变主档编号，也不能重新启用主档已停用账号。
- 主页动作在点击时重新读取当前主档位置，不长期缓存 URL。
- 不要手工排序、删除数组项或把空项挤掉。

### 数据影响、风险与恢复

账号任务只有勾选“将所选账号 earliest 同步写回 settings_master.json”时才写主档 `earliest`，并保证主档 `enable` 不变。账号审计应用可把 `enable` 改为 `false` 或恢复为 `true`，但不改数组长度和其他字段。错误手工重排无法靠任务日志可靠恢复；应使用写入前备份还原完整主档，并重新检查 A 编号一致性。

## 8. 观察名单、W 编号、提醒与转正

### 设计目的与身份边界

观察名单用于保存“需要以后复查、暂不进入正式采集”的账号。W 正文只存在于 `<管理器目录>/Data/watchlist.json`，高水位和请求收据另存于同一 `Data` 下的两个控制文件；W 不占 A 编号，不进入正式 Excel、任务模板或下载设置。W 编号通过独立高水位单调分配，归档、删除、转正或恢复都不会回收旧编号。

持久状态只有“观察中”“已转正”“已归档”。“已到期”“已超期”和“待复查”由下次复查时间计算：提醒已到但仍在同一本地日期为到期，跨过本地日期后为超期。

### 查看、筛选与主页

1. 打开“观察名单”，用“状态”“复查”和搜索框筛选。
2. 选择一行后可点击“打开主页”。程序只把通过安全校验的单个地址交给默认浏览器，不在页面或日志回显完整地址。
3. 总览“查看观察名单”和导航角标可直接定位待处理记录；不使用 Windows 系统通知。

### 复查、归档与删除

1. 选择“观察中”记录，点击“复查/编辑”。
2. 可修改观察名称，选择作品较少、更新不确定、内容待核对、疑似私密或其他原因，填写备注并设置下次复查日期。
3. “其他”原因必须有备注；保存会追加复查历史，不会覆盖原始采集身份。
4. 不再观察时点击“归档”。
5. 选择已归档记录可“恢复观察”，并填写新的下次复查时间。
6. “永久删除归档”只对已归档记录可用，确认后删除正文，但 W 编号永不复用。

### 转为正式账号

1. 选择观察中的记录，点击“预览转正”。
2. 核对目标 A 编号、正式重复状态和身份字段；缺少必要身份时停止并重新识别，不能按显示名称猜测。
3. 预览为可执行状态后点击“确认转正”，再确认正式 JSON 与 Excel 的写入边界。
4. 只有正式双文件完成事务写入和复读，且 W 记录成功更新为“已转正”并显示 A 编号，才算完整成功。

### 数据影响与风险

复查、归档和恢复会原子更新 `watchlist.json`；W 高水位和请求收据分别保存在 `watchlist_w_watermark.json` 与 `watchlist_control.json`。转正先保存恢复意图，再调用正式双文件服务。任何正式写入失败都必须保留 W 记录。

### 失败与恢复

- “数据已更新，请刷新后重试”：点击“刷新观察名单”，重新选择并复查。
- `READ_ONLY`、`BUSY` 或 `RECOVERY_REQUIRED`：停止新写入，先完成 Startup/收据/正文对账。
- 正式写入成功但 W 状态未完成：保留“转正修复中”记录，不删除、不归档、不再次正式追加。
- 只有预览明确显示“需要重试”，并且已确认正式 JSON、Excel 均不存在目标且没有未完成事务时，才使用“明确重试转正”。
- 正式目标已存在且联合对账唯一一致时，确认动作只完成 W 恢复，不追加第二个 A。

## 9. 账号任务、范围表达式与批次生成

### 设计目的与使用前提

任务模板是可重复使用的账号选择和 `earliest` 规则，不是第二份主档。创建任务前必须有可读主档，并处于 `READY`。

### 单个或混合任务

1. 打开“账号任务”，输入如 `A1,A10-A12,A20` 或不带 A 前缀的等价表达式。
2. 填写可选任务名称；同名文件会自动递增，不覆盖旧模板。
3. 选择 `earliest` 保持、清空或设置数值/日期/文本，并填写对应值。
4. 需要写回主档时才勾选“将所选账号 earliest 同步写回 settings_master.json”。
5. 可勾选“智能跳过近期已确认私密账号”并设置参考天数。预览只根据可靠历史证据跳过，不把错误、中断或未开始猜成私密。
6. 先点“预览”，再选择“只创建任务模板”“创建并设为正式 settings.json”或“创建、激活并开始下载”。
7. 智能跳过弹窗可选择“按预览跳过”“强制包含全部”或“取消创建”。

### 批次生成

1. 打开“批次生成”，填写开始 A、结束 A 和每批账号数。
2. 选择统一 `earliest` 规则。
3. 点击“生成全部批次任务”。所有批次先完成校验后才逐一写入。

### 数据影响与风险

模板写入 `<管理器目录>/Data/Tasks/*.json`。模板中只有所选且主档仍启用的账号为启用，`run_command` 固定为批量下载命令。激活会在写前创建 `BeforeChange` 关键文件快照，再写唯一正式 `settings.json`。只有明确勾选主档持久化时才写主档 `earliest`。

### 失败与恢复

- 表达式越界、批次结束编号超过主档或所选账号全被停用时不生成有效任务。
- 批次中途写入失败会删除本次已生成文件；若仍有残留，界面会明确列出，需人工核对后再重试。
- 激活失败时从 `BeforeChange` 恢复正式设置；不要把任务模板手工复制到 Volume 绕过备份。

## 10. 下载队列、暂停、取消、监听与完成后处理

### 设计目的与使用前提

下载器始终只读取唯一正式 `settings.json`。队列按用户保存的模板顺序逐个执行“备份、激活、启动、汇总、后处理”，并保证同一时间只有一个 `main.exe`。

### 队列准备与顺序

1. 打开“下载队列”，点击“刷新任务列表”。
2. 勾选决定哪些模板参加队列；高亮只决定当前排序操作对象，两者不要混淆。
3. 高亮任务后选择移到最前、上/下一位、最后或指定位置，再点“移动高亮任务”。也可用 `Alt+Up` / `Alt+Down`。
4. “恢复按 A 编号排序”会清除人工槽位顺序；顺序保存于 `Data/task_order.json`。
5. “删除已选模板”只删除 `Data/Tasks` 中勾选的 JSON，不删除历史日志、数据库或正式设置。

### 运行与控制

1. 单独激活时只勾选一个模板，点击“应用为正式 setting”。
2. “运行当前 setting”直接运行现有正式设置；“按顺序运行已选”按当前列表顺序逐项激活和运行。
3. 按需设置截图归档、索引刷新、清理复查和结果查看。
4. “暂停队列”只阻止启动下一个模板，不暂停当前下载进程；再次点击继续队列。
5. “取消全部下载任务”会结束当前由管理器启动的批量下载并清空本次剩余队列，不删除模板或数据。
6. “下载结束后保留黑框”开启时，必须在下载器黑框按键结束后才继续后续步骤。
7. “全部任务完成后正常关机”只有在任务、汇总和后处理可靠完成且采集服务未启用时才进入 60 秒可取消倒计时。

### 后台监听

“启动后台监听”把正式设置的运行命令原子切换为监听模式并启动引擎；“停止后台监听”先正常停止进程，确认退出后恢复批量下载命令。监听期间不要启动批量队列。

### 数据影响、风险与恢复

每次激活写 `settings.json` 并创建关键文件备份；每个下载进程生成一份 `Logs/DownloadTasks/DownloadTask_*.log`，原生日志仍在正式 Volume 的日志目录。下载会修改数据库和视频内容，程序回退不能撤销这些业务写入。异常退出后停止剩余队列，先检查任务日志和正式设置，再决定是否重跑。

## 11. 下载结果、结果看板与打开主页

### 设计目的

“下载结果”用于快速筛选账号级历史行；“结果看板”用于选择单个任务并查看完整性、可靠性、六类主状态、关注账号和证据。两者只读取既有任务日志，不建立第二套业务数据库。

### 下载结果

1. 按状态、A 编号和任务名称筛选，或点击“立即刷新结果”。
2. 选中一行后点击“打开主页”。程序按当前主档的 A 位置读取地址；不会从 Excel 猜测。
3. 双击“来源日志”单元格仍只打开对应任务日志，不会打开主页。

### 结果看板

1. 从“任务”下拉框选择一个任务；“刷新”会强制重读任务索引和当前任务。
2. 查看计划账号、实际开始、完整性、可靠性、附加异常、未进入处理和六类主状态。
3. 在“账号关注与定位”中选择“需关注”“全部账号”或具体状态，并用 A 编号搜索。
4. 选中单个账号后点击“打开主页”。
5. “打开任务日志”查看管理器任务日志；有可靠原始片段时可选择并“打开原始日志”。

### 结果口径

六类互斥主状态为有新作品下载、作品均被跳过、无符合条件作品、私密账号、处理异常和处理中断。“完成但有异常记录”是附加状态，可与主状态重叠。证据不全时保留未知或部分结果，不用 0 填补未知。

### 数据影响、风险与恢复

刷新、筛选、看板和主页解析均只读业务文件；把合法主页交给默认浏览器后，浏览器可能产生自身历史或缓存。主页失败只显示固定错误，不回显地址。任务日志被移动或内容变化时刷新索引；不要用旧看板缓存判断当前正式数据。

## 12. 账号审计、永久停用与生命周期

### 设计目的与使用前提

账号审计把主档位置、任务汇总和可选的精确原生日志区间整理为建议。建议不会自动生效；用户确认后只改变主档 `enable` 或审计旁路状态，不删除或重排 A 编号。

### 操作步骤

1. 打开“账号审计”，设置连续错误阈值和最少证据轮次。
2. 日常审计保持“含原生日志分析（慢）”关闭；准备永久停用或核查特殊原因时才开启。
3. 点击“重新审计”，等待报告完成。原生日志分析不是联网检测。
4. 用建议停用、建议恢复、需复核、重复或已停用筛选，并可查找 A 编号。
5. 选中单行可“打开主页”；可多选行后设置“继续启用”“永久停用”或“待复核”。
6. 点击“预览并应用决定”，核对停用、恢复、待复核和应用后启用数量，再确认。
7. 不准备应用时用“清空未应用的决定”；扫描或写入前阶段可用“取消当前审计操作”。

### 数据影响与风险

应用前创建 `BeforeAccountAudit` 完整 Volume 备份。正式主档只改变目标位置的 `enable`，并复读验证数组长度和其他字段；待复核写入 `<管理器目录>/Data/AccountAudit/audit-state.json`。至少保留一个启用账号。旧任务模板激活时仍服从最新主档停用状态。

### 失败与恢复

- 请求失败不等于账号被封、注销或不可用；身份冲突和重复必须人工复核。
- 主档在审计后变化时应用会拒绝，必须重新审计。
- 引擎或采集服务运行时禁止应用决定。
- 临界写入失败会尝试从完整备份恢复主档和审计侧档；恢复也失败时停止使用写入功能并保留备份路径和错误。

## 13. 截图归档、索引与快捷方式清理

### 设计目的与使用前提

截图归档只把可识别截图移动到对应视频账号目录；索引只读取视频账号目录并维护受管理快捷方式。任何删除都必须限制在 `<索引目录>` 顶层且带管理器标记的 `.lnk`。

### 操作步骤

1. 打开“截图与索引”，先核对截图收件箱、视频账号目录和快捷方式索引路径。
2. 点击“预览截图归档”，查看识别账号文件夹、识别截图、可安全归档、缺失目录和同名目标数量。
3. 确认后点击“立即安全归档截图”。
4. 点击“立即刷新索引”创建或更新快捷方式，并自动清理两类受管理失效项。
5. 只需维护或重试删除时，点击“立即重新扫描并清理快捷方式”。
6. “安全自检清理功能”使用隔离临时夹具验证规则，不应读取或修改正式视频/索引目录。

### 数据影响与风险

归档会移动截图收件箱中的文件；目标已有同名文件时跳过，不覆盖。索引刷新可创建、更新或删除受管理 `.lnk`，但不修改视频源目录。索引刷新和清理日志分别写入 `Logs/IndexRefresh` 与 `Logs/IndexCleanup`。

### 失败与恢复

- 预览和执行数量不一致时停止，核对是否有外部程序同时改动目录。
- 找不到账号文件夹或目标同名时保留源截图，修正目录后重新预览。
- 清理失败时保留失败项，可关闭占用程序后运行独立清理重试。
- 不要手工扩大清理范围，也不要把普通用户快捷方式改成受管理标记。

## 14. 下载引擎更新、回退与受保护目录

### 设计目的与使用前提

更新和回退只替换引擎程序文件，永久保留唯一正式 `_internal/Volume`。操作前必须停止下载引擎和账号采集服务，并确保设置页路径检查为 `READY`。

### 安全更新

1. 在“设置”的“下载引擎安全更新”选择受信任的 Windows X64 ZIP。
2. 点击“只读预检更新包”，核对结构、主程序、内部目录、哈希和 Volume 边界。
3. 预检通过后点击“备份并安全安装”，阅读确认信息后继续。
4. 程序先创建 `BeforeEngineUpdate` 完整 Volume 备份，再把旧引擎保存到 `Updates/EngineRollback/<时间>`，把当前正式 Volume 移入新引擎的固定位置，最后复读校验。

### 回退到历史引擎

1. 点击“刷新列表”，等待回退点和磁盘占用统计。
2. 选中一行，必要时编辑备注，再点击“预检回退点”。
3. 状态为可用时点击“执行回退”并确认。无清单但结构完整的旧点会有额外警告和第二次确认。
4. 缺少 `main.exe`、缺少内部目录、哈希不符、不可读或候选含 Volume 的回退点一律拒绝，确认不能绕过。
5. 回退前创建 `BeforeEngineRollback` 完整备份，被换下的当前引擎保存到 `Updates/EngineSuperseded/<时间>`。

### 数据影响与风险

更新/回退会移动程序目录并复制完整 Volume 备份，但成功前后正式数据库、主档和设置必须保持同一业务内容。受保护目录中只允许一个正式 Volume；不要手工把历史点的 `_internal/Volume` 拷回当前引擎。

### 失败与恢复

移动、哈希、JSON 或 SQLite 校验失败时程序尝试恢复原引擎、正式 Volume 和候选来源。若恢复失败，停止运行下载器，保留完整备份、`EngineRollback`、`EngineSuperseded` 和错误信息，先人工核对目录边界。不要删除包含 Volume 的 `_internal`，也不要用无清单警告强行通过其他拒绝状态。

## 15. 日志统计、诊断导出与隐私边界

### 设计目的与使用前提

日志统计只分析任务日志声明的精确原生日志区间，保存白名单统计量，并从当前进程缓存导出中英文安全报告。它不修改日志，也不推断账号封禁或注销。

### 操作步骤

1. 在“结果看板”选择一个已完成且具有可靠日志区间的任务。
2. 展开“本次运行日志统计（只含统计量）”。
3. 当前运行可用时点击“分析本次日志”；历史任务点击“分析该任务日志”。
4. 等待分析完成。需要停止时点击“取消”。
5. 统计成功后点击“导出中英文安全诊断报告”。
6. 只有“最近一次导出”显示产物自检 clean，且中英文文件均成功写入，才可分享报告。

### 数据影响与隐私

分析只读受管理区间，结果保存在进程内缓存。导出写入 `<管理器目录>/Logs/Diagnostics`，只含固定端点、状态码、日志级别、签名字段存在次数、失败分类等白名单统计，不含 Cookie、Token、账号标识、作品标识、昵称、本地路径或 URL 查询串。

### 失败与恢复

- 旧日志缺少精确范围、文件缺失或区间部分可用时显示 `MISSING_RANGE`、`MISSING_FILE` 或部分结果，不猜测边界。
- 读取错误、非法编码、区间越界或统计上限会明确失败/截断。
- 自检命中高风险字段时，中英文最终文件都不得留下；修正统计来源后重新分析，不要编辑临时文件冒充安全报告。
- 导出使用缓存，不会为了恢复导出而重新读取原生日志。

## 16. 常见完整工作流示例

以下示例只描述操作顺序，账号、路径和结果均应使用当前受控环境中的有效数据。

### 从正式采集到顺序下载

1. 启动管理器并等待 `READY`。
2. 在“账号采集”启动服务，在浏览器脚本完成正式双文件采集，再停止服务。
3. 在“账号任务”预览并创建模板，或在“批次生成”生成多个模板。
4. 在“下载队列”勾选模板、调整顺序和后处理选项。
5. 点击“按顺序运行已选”，按需查看黑框，等待每项汇总和后处理完成。
6. 在“下载结果”定位账号行，在“结果看板”核对完整性和异常。

### 从观察记录到正式账号

1. 启动管理器采集服务，在账号主页使用当前内置油猴脚本的“加入观察”按钮向本机观察接口提交记录；确认返回 W 编号和“观察中”。
2. 在“观察名单”筛选记录，使用“复查/编辑”补充原因、备注和提醒。
3. 需要正式采集时先“预览转正”，再“确认转正”。
4. 等正式 JSON、Excel 和 W 状态三方均确认成功后，再到“账号任务”使用新 A 编号。
5. 任一方结果不确定时停在恢复状态，先联合对账，不重新追加。

### 审计后停用账号

1. 在“账号审计”生成只读报告。
2. 查看建议、身份风险和证据轮次；需要时单独打开主页人工核对。
3. 对选中行设置决定，预览应用范围。
4. 确认后等待完整备份和复读验证完成。
5. 重新创建或激活任务，确认旧模板不能重新启用已停用账号。

### 更新后回退引擎

1. 停止队列、监听和采集，预检更新 ZIP。
2. 执行“备份并安全安装”，确认正式 Volume 内容不变。
3. 需要回退时刷新历史点并只读预检。
4. 执行回退，确认旧版本恢复、当前版本进入 `EngineSuperseded`、正式 Volume 仍唯一。
5. 程序版本回退后重新审视新版本期间的数据写入，不能假设数据库自动回退。

## 17. 故障排查、失败恢复与禁止操作

### 常见故障

| 表现 | 先检查 | 正确处理 |
| --- | --- | --- |
| 启动停在只读保护 | 总览摘要、技术详情、路径和 Startup 快照 | 修正路径或恢复有效观察快照，再“重新检查” |
| 按钮不可用 | 是否 `READY`、是否有有效选择、是否已有冲突后台任务 | 等当前任务终态，刷新页面并重新选择 |
| 主页未打开 | A/W 是否存在、地址是否通过安全校验、默认浏览器是否接受 | 处理主档/观察数据错误；不要从 Excel 猜地址 |
| 任务没有账号 | 主档停用状态、表达式范围、智能私密跳过结果 | 重新预览，必要时人工选择“强制包含全部” |
| 队列不继续 | 是否暂停、黑框等待按键、汇总/后处理仍在运行 | 完成当前交互或取消，不强杀管理器 |
| 观察转正不确定 | W 恢复意图、正式 JSON/Excel 是否唯一一致 | 停止新写入并联合对账；仅按预览允许的恢复动作继续 |
| Startup 恢复后仍 blocked | 当前快照正文、收据、高水位或正式对账未通过 | 保留所有快照，选择正确有效快照再恢复 |
| 诊断导出被拒绝 | 是否有缓存统计、自检是否 clean | 重新选择可靠任务分析；不要手改报告绕过自检 |

### 禁止操作

- 禁止同时运行两个管理器、两个下载引擎，或新旧版本并行访问同一正式数据。
- 禁止手工重排/删除 `accounts_urls`、复用 A/W 编号或降低 W 高水位。
- 禁止把观察记录直接写进正式主档、Excel、任务模板或 `settings.json`。
- 禁止在更新/回退时覆盖、复制或删除受保护的正式 Volume。
- 禁止把任意路径当回退点、原生日志统计源或快捷方式清理目标。
- 禁止在正式写入结果不确定时盲目重试。
- 禁止用强制结束线程/进程代替正常取消和关闭。
- 禁止把正式 URL、UID、昵称、mark、Cookie、Token、原始日志和正式路径提交到源码、截图或诊断报告。

### Startup 六文件快照

观察三文件已经存在且有效时，每份 V0.1.7 Startup 快照包括 `settings_master.json`、`settings.json`、`DouK-Downloader.db`、`watchlist.json`、`watchlist_w_watermark.json` 和 `watchlist_control.json`，并有 manifest、大小、SHA-256 和 SQLite quick check。最多保留 20 份有效六文件快照；空间不足、快照无效或联合对账未完成时先保留旧快照，暂停轮换。扫描到的无效目录进入 Startup 的受控隔离区，不计入 20 份。

首次启用时，启动流程在锁内确认可信首次启用证据后创建三个空观察文件，将初始化状态提交为 `complete` 并先关闭写闸门，再创建首个六文件 Startup 快照、保存 installation identity，最后在同一启动会话中重新开放写闸门并进入 `READY`。只缺部分文件、已存在历史/installation identity 但文件缺失，或首次启用证据不明确时，启动会阻止继续；不能通过手工创建文件、复制合成夹具或降低高水位绕过。

### 恢复观察数据

1. 停止下载引擎和采集服务。
2. 在“设置”的“Startup 观察数据恢复”选择 `Backups/Startup/<时间>` 的直接快照目录。
3. 点击“恢复观察数据”并确认。该入口只恢复三个观察 Data 文件；正式 Volume、Excel、数据库和任务模板不恢复。
4. W 高水位和请求收据按不可回退规则合并，随后自动执行完整启动检查。
5. 只有界面返回 `READY` 才恢复观察写入；仍 blocked 时保留全部快照并继续对账。

### 迁移原则

迁移管理器时整体保留 `Data`、`Logs`、`Backups` 和 `Updates`，但正式 Volume 仍由下载引擎路径决定。迁移旧采集器只复制 Excel/分类/截图并补齐尾部，不复制第二份主档。跨机器迁移前还要核对默认浏览器、下载引擎依赖、视频目录、索引目录，以及未放在管理器目录内的用户范围 UI 偏好；不要把浏览器 Cookie 或其他用户级配置打包进项目数据。
