# DouK-Manager v0.1.2 Log Categories Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Route all five kinds of newly created logs into dedicated English subdirectories under the portable manager `Logs` directory without migrating old logs or changing index safety behavior.

**Architecture:** `ManagedPaths` owns five derived log directories. Python services write manager, collector, and download-task logs directly to their assigned directories; `IndexService` passes explicit log roots to PowerShell, and the scripts never derive logs from `IndexRoot`. The repository-level refresh wrapper supplies a portable default relative to its own location.

**Tech Stack:** Python 3.12+, `pathlib`, `unittest`, PowerShell 5.1/.NET path APIs, PyInstaller, GitHub Actions.

## Global Constraints

- Work only in `feature/v0.1.2-log-categories`, based on current `origin/develop`.
- Do not modify `main`, `v0.1.0` Tag, or any Release.
- Do not read, write, migrate, or test against formal `F:\DouK-Manager`, `F:\Douk videos`, `_internal\Volume`, `DouK-Downloader.db`, `settings_master.json`, or `settings.json`.
- All tests use `TemporaryDirectory`, mocks, and synthetic data.
- Do not scan, move, rename, delete, or copy old logs.
- Use exactly `Manager`, `Collector`, `DownloadTasks`, `IndexRefresh`, and `IndexCleanup`.
- Preserve the approved file-name prefixes and timestamp precision.
- Do not add dependencies, networking, installers, registry writes, or system Python changes.
- v0.1.2 is a `develop` artifact version only; do not create a v0.1.2 Tag or Release.
