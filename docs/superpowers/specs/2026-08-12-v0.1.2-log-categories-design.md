# DouK-Manager v0.1.2 日志分类设计

## 目标

将管理器产生的五类新日志统一写入便携目录 `Logs` 下的五个英文子目录，避免管理器日志散放在同一级，也避免索引日志继续写入索引目录自身的 `Logs`。

本变更作为 `develop` 上的 v0.1.2 开发迭代实施，不创建 v0.1.2 Tag 或 Release，不进入 `main`，不修改、移动或覆盖 `v0.1.0` Tag/Release。

## 目录布局

管理器运行根目录下形成以下结构：

```text
Logs\
├─ Manager\
├─ Collector\
├─ DownloadTasks\
├─ IndexRefresh\
└─ IndexCleanup\
```

在正式便携目录中对应：

```text
F:\DouK-Manager\Logs\Manager
F:\DouK-Manager\Logs\Collector
F:\DouK-Manager\Logs\DownloadTasks
F:\DouK-Manager\Logs\IndexRefresh
F:\DouK-Manager\Logs\IndexCleanup
```

源码不得硬编码 `F:\DouK-Manager`。所有路径必须从当前 `application_root()` 或测试传入的临时根目录派生。

## 日志分类与命名

五类新日志保持原有前缀和按时间排序的命名风格：

| 类型 | 子目录 | 新日志命名 |
| --- | --- | --- |
| 管理器本体 | `Manager` | `DouKManager_yyyy-MM-dd_HH-mm-ss-ffffff.log` |
| 采集器 | `Collector` | `Collector_yyyy-MM-dd_HH-mm-ss.log` |
| 下载任务 | `DownloadTasks` | `DownloadTask_yyyy-MM-dd_HH-mm-ss-ffffff.log` |
| 索引刷新 | `IndexRefresh` | `Refresh-DoukIndex-RunLog_yyyy-MM-dd_HH-mm-ss-fff.txt` |
| 索引清理 | `IndexCleanup` | `Cleanup-Broken-Shortcut-Report_yyyy-MM-dd_HH-mm-ss-fff.txt` |

Python 的管理器日志和下载任务日志继续保留微秒，避免同一秒创建多个文件时发生重名。PowerShell 索引日志继续使用毫秒。采集器日志维持当前秒级格式。

当前源码的清理脚本前缀是 `Cleanup-BrokenDoukIndex-RunLog`，与用户现有旧日志 `Cleanup-Broken-Shortcut-Report` 不一致。本次将新日志统一为用户指定的 `Cleanup-Broken-Shortcut-Report`，但不重命名任何旧文件。

## 路径模型

`ManagedPaths` 保留总日志目录 `logs`，并增加五个明确路径：

- `manager_logs`
- `collector_logs`
- `download_task_logs`
- `index_refresh_logs`
- `index_cleanup_logs`

`ManagedPaths.from_config()` 从 `app_root / "Logs"` 派生这些目录。`ensure_manager_directories()` 创建总目录及五个子目录，使控制器、服务和索引脚本调用前都有稳定目标。

界面的“打开日志目录”继续打开总目录 `paths.logs`，不改变用户入口。

## Python 写入调用链

- `ManagerController.__init__()` 将 `setup_logging()` 的目标从 `paths.logs` 改为 `paths.manager_logs`。
- `CollectorService.start()` 将采集器日志写入 `paths.collector_logs`。
- `EngineService.start()` 将单次下载进程日志写入 `paths.download_task_logs`。
- `IndexService.refresh()` 接收或持有管理器路径后，向刷新脚本传入 `-LogRoot <paths.index_refresh_logs>`。
- `IndexService.cleanup()` 向清理脚本传入 `-LogRoot <paths.index_cleanup_logs>`。

索引服务的公共业务语义保持不变：源目录和索引目录仍由现有配置决定，日志目录只影响报告文件保存位置，不参与快捷方式扫描或删除判断。

## PowerShell 参数设计

正式脚本增加显式参数：

```powershell
[Parameter(Mandatory)]
[string]$LogRoot
```

脚本使用现有路径规范化函数解析 `LogRoot`，不存在时创建目录，并直接在该目录生成日志。正式脚本不再通过 `$IndexRoot\Logs` 推导日志位置，也不在索引目录中创建 `Logs`。

根目录兼容入口 `Refresh-DoukIndex.ps1` 增加可选参数：

```powershell
[string]$LogRoot = (Join-Path $PSScriptRoot 'Logs\IndexRefresh')
```

它继续通过 `@PSBoundParameters` 调用正式脚本，因此脱离 GUI 手动运行时默认写入管理器源码/便携目录的 `Logs\IndexRefresh`。调用者显式传入 `-LogRoot` 时使用调用者路径。

清理脚本没有仓库根目录兼容入口；管理器调用时必须显式传入 `Logs\IndexCleanup`。

## 旧日志边界

本版本不执行以下操作：

- 不扫描 `F:\DouK-Manager\Logs` 或 `F:\Douk videos\Logs` 的旧文件。
- 不迁移、复制、移动、重命名或删除旧日志。
- 不创建迁移状态文件。
- 不尝试按旧前缀自动分类。

用户自行将旧日志复制到对应子目录。新版只负责创建五个目录并将修改后产生的新日志写入正确位置。

## 错误处理与安全

- 子目录不存在时创建；创建或写入失败时返回现有错误链路中的明确异常。
- 索引脚本不得在新日志目录写入失败时回退到 `$IndexRoot\Logs`，防止日志再次分散或掩盖权限问题。
- 日志路径变更不得改变索引快捷方式创建、更新、删除范围或安全判断。
- 所有自动测试使用 `TemporaryDirectory`、合成目录和测试快捷方式；不得访问正式 `F:` 数据、正式 `_internal\Volume` 或正式日志目录。
- 本变更不读取或修改 `DouK-Downloader.db`、`settings_master.json`、`settings.json`。
- 不安装依赖，不修改本机 Python，不增加联网、注册表或安装器行为。

## 测试设计

新增或更新测试覆盖：

1. `ManagedPaths` 从临时应用根目录派生并创建五个日志子目录。
2. 管理器本体日志只写入 `Manager`，文件名前缀和时间格式保持兼容。
3. 采集器日志写入 `Collector`。
4. 下载任务日志写入 `DownloadTasks`，内容与现有任务日志语义不变。
5. 索引刷新命令显式传入 `-LogRoot`，脚本写入 `IndexRefresh`。
6. 索引清理命令显式传入 `-LogRoot`，脚本写入 `IndexCleanup`。
7. 刷新脚本仍生成 `Refresh-DoukIndex-RunLog_*.txt`。
8. 清理脚本生成 `Cleanup-Broken-Shortcut-Report_*.txt`。
9. 正式脚本不再包含 `$logRoot = Join-Path $idxFull 'Logs'`，并且测试索引目录下不会新建日志文件。
10. 根目录兼容入口默认将日志写入自身 `Logs\IndexRefresh`，同时保持显式参数转发。
11. Windows 索引集成测试使用临时目录确认真实生成位置和汇总解析。
12. 运行全部现有测试，确认采集运行时安全、单下载引擎、任务配置和数据库保护逻辑不受影响。

## Windows 实机验收

构建 artifact 后由用户在保留旧版本副本的前提下验证：

1. 停止管理器、采集器和下载引擎，替换 artifact 中的三个便携文件。
2. 启动管理器，确认 `F:\DouK-Manager\Logs` 下自动出现五个英文子目录。
3. 确认本次启动生成的新 `DouKManager_*.log` 位于 `Manager`。
4. 启动并停止采集器，确认 `Collector_*.log` 位于 `Collector`。
5. 运行一个测试下载任务，确认 `DownloadTask_*.log` 位于 `DownloadTasks`，同时确认仍只允许运行一个下载引擎。
6. 执行索引刷新，确认 `Refresh-DoukIndex-RunLog_*.txt` 位于 `IndexRefresh`，且 `F:\Douk videos\Logs` 不产生新日志。
7. 执行索引清理，确认 `Cleanup-Broken-Shortcut-Report_*.txt` 位于 `IndexCleanup`，且索引目录只处理既有受管快捷方式范围。
8. 点击“打开日志目录”，确认打开总目录并能看到五个子目录。
9. 确认旧日志未被移动、改名或删除。

## 回滚

回滚只需停止相关进程，并恢复此前保存的 v0.1 便携文件。日志目录变更不修改数据库或配置；回滚后，新版本已经生成的五个子目录和日志可以保留，也可由用户手动整理。不得使用回滚过程移动或覆盖正式数据库与配置。
