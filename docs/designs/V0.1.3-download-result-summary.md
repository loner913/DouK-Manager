# DouK-Manager V0.1.3 下载结果汇总设计规格

状态：已获用户确认

设计日期：2026-08-13

目标分支：`develop`

实现仓库：DouK-Manager

下载引擎：TikTokDownloader（本功能不修改）

## 1. 背景与目标

当前下载进程退出码 `0` 只表示下载器进程正常退出，不能证明所有计划账号均成功获取或下载作品。V0.1.3 在每个下载进程结束后分析本次 TikTokDownloader 原生日志，在管理器信息框和已有的 `DownloadTask_*.log` 中提供账号级结果汇总。

最低输出包括：

- 本次计划账号数；
- 实际开始账号数；
- 各账号主状态的数量；
- 私密、异常、中断、未开始账号的完整 A 编号；
- 结果是否完整、是否通过一致性校验；
- 本次原生日志的绝对路径。

V0.1.3 暂不统计或展示视频、图集、实况的作品总数。

## 2. 非目标与安全边界

- 不修改 TikTokDownloader 源码或运行行为。
- 不读取、复制、修改或删除 `DouK-Downloader.db`。
- 不修改或复制原生日志。
- 不生成压缩日志、目录快照文件或独立结果 JSON。
- 不从正式 `Volume` 读取测试数据，不在正式目录执行开发验证。
- 不把 Cookie、Token、请求头、完整 URL、响应内容或大段原始错误写入管理器日志。
- 不根据退出码 `0` 推断账号下载成功。

日志目录快照仅存在于内存。汇总结果追加到每次任务原本就会创建的 `DownloadTask_*.log`，不额外积累缓存文件。

## 3. 计划账号与身份映射

管理器启动下载进程前，从当时已激活的 `settings.json` 读取 `accounts_urls`。只有同时满足以下条件的账号属于本次计划：

```text
enable=true
url 非空
```

本次 `enable=false` 或 URL 为空的账号完全排除：不计入计划数、任务内序号、未开始或任何结果状态。

A 编号以 `accounts_urls` 的数组位置为权威：数组第 N 项对应 `A<N>`。启动时冻结启用且 URL 为非空字符串的完整 `mark`；正常账号日志与冻结 `mark` 精确相等，启动前错误也只按完整 `mark` 匹配。私密账号可仅按任务内序号映射。不使用 A 编号前缀回退，因此 `A10other` 不会误匹配 `A1`，而 `A1164example` 也可作为数组第 116 项的合法完整 mark。

管理器按计划账号在数组中的原始顺序建立不可变的内存映射。例如本次只启用 `A50、A53、A80`：

```text
任务内第 1 个账号 -> A50
任务内第 2 个账号 -> A53
任务内第 3 个账号 -> A80
```

下载期间主档新增或修改账号不得改变本次映射。正常账号日志中的 `标识：A编号` 用于交叉校验；私密账号未输出标识时，使用冻结映射确定 A 编号。进程非零退出时，如果最后一个账号只来得及输出“开始处理第 N 个账号”而尚未输出标识，可使用冻结任务序号将该账号标记为“处理中断”；该例外只适用于日志中最后一个未完成账号。任何已输出但不一致的标识，以及中间账号缺少标识，仍停止可信结果判定，不输出可能错误的账号列表。

已核查当前下载引擎源码：`accounts_urls` 会先过滤 `enable=false` 或 URL 为空的条目，其余账号按数组顺序串行处理，不重排、不并发。

## 4. 原生日志定位

启动下载进程前，管理器在内存记录日志目录中已有 `.log` 文件的：

```text
绝对路径
文件大小
最后修改时间
```

进程结束后再次检查目录：

1. 优先选择本次运行期间新增的日志文件。
2. 如果没有新增文件，选择本次运行期间发生增长的文件，并从启动前文件大小的偏移位置开始分析。
3. 使用任务起止时间、计划账号数、首个处理序号等内容校验候选文件。
4. 不能唯一确定时停止账号结果判定，报告“无法可靠汇总”。
5. 如果本次内容跨多个文件，记录完整原始路径列表。

不得只选择目录中最后修改或名称最新的日志。

已核查当前下载引擎源码：Windows 日志使用 `UTF-8-SIG`，默认以程序启动时间命名。定位方案仍保留对追加已有日志的兼容，避免依赖未经运行验证的单一假设。

## 5. 汇总时机与队列顺序

下载引擎运行期间不读取、不监听原生日志。每个进程结束后的顺序固定为：

```text
下载进程结束
-> 信息框显示“正在汇总账号结果”
-> 后台逐行读取本次日志区间
-> 建立账号处理块并判定状态
-> 执行身份和统计一致性校验
-> 追加写入 DownloadTask_*.log
-> 一次性更新信息框
-> 才允许启动队列中的下一任务
```

逐行读取表示每次只处理当前行，不把几十 MB 日志整体载入内存；它不表示下载期间实时刷新界面。

正常退出、非零退出、崩溃和用户主动停止都执行汇总。任何队列任务都必须等待本次汇总完成，避免日志边界和账号归属混淆。

## 6. 账号状态模型

### 6.1 已开始账号的主状态

每个已进入账号处理流程的账号只能归入一个主状态：

- **有新作品下载**：日志最终统计的下载作品数大于 `0`。
- **作品均被引擎跳过**：筛选后有作品，视频、图集和实况最终全部计入跳过。
- **无符合条件作品**：筛选处理后的作品数量为 `0`，且不存在更高优先级异常。
- **私密账号**：出现明确的私密账号提示。
- **处理异常，需核对**：账号块出现无法确认已恢复的错误。
- **处理中断**：已开始处理，但进程结束前没有形成可确认的最终结果。

判定优先级：

```text
私密账号
-> 无法恢复的处理异常
-> 处理中断
-> 有新作品下载
-> 作品均被引擎跳过
-> 无符合条件作品
```

### 6.2 附加状态

- **完成但有异常记录**：出现网络异常、下载中断或重试，但随后形成完整作品统计。

该状态只是附加备注，不重复计入主状态总数。例如账号可以是“有新作品下载，同时完成但有异常记录”。单条 `WARNING` 或 `ERROR` 不能自动等同于整个账号失败。

### 6.3 未进入正常处理流程的计划账号

下载引擎会在输出“开始处理第 N 个账号”前解析 URL：

- URL 或 `sec_user_id` 解析失败并继续后续账号时，归入 **处理异常，需核对**；该账号不算实际开始，也不算未开始。
- 因停止、崩溃或异常退出而尚未轮到的剩余计划账号，归入 **未开始**。
- 非零退出前最后一个账号已经输出“开始处理第 N 个账号”、但尚未输出标识时，按启动前冻结的任务序号归入 **处理中断**；只要日志曾输出冲突标识，就不得使用该回退。

不得把所有未出现“开始处理”的账号一律判为未开始。

## 7. 统计与完整性校验

实际开始按日志中出现的有效且不重复的任务内序号计算，不使用最大序号代替。

一级核对公式：

```text
计划账号 = 实际开始 + 进入处理前异常 + 未开始
```

二级核对公式：

```text
实际开始 =
  有新作品下载
  + 作品均被引擎跳过
  + 无符合条件作品
  + 私密账号
  + 已开始后的处理异常
  + 处理中断
```

“完成但有异常记录”不进入上述加总。

遇到以下任一情况，结果标记为“不完整”或“无法可靠确认”：

- 日志文件缺失或无法唯一定位；
- 序号重复、越界或缺失原因无法判定；
- 日志标识与冻结映射不一致；
- 统计公式不成立；
- 日志截断、编码或读取错误导致证据不足；
- 计划账号未全部完成；
- 用户停止、进程崩溃或异常退出。

结果不完整时仍展示截至进程结束前能够可靠确认的部分结果，但不得声称全部成功。

## 8. 信息框输出

信息框在汇总结束后一次性显示，例如：

```text
下载进程：正常退出（退出码 0）
账号汇总：任务未完整执行

计划账号：50
实际开始：31
【已开始账号主状态（互斥，以下六项合计=实际开始）】
有新作品下载：8
作品均被引擎跳过：17
无符合条件作品：3
私密账号：2
处理异常，需核对（已开始主状态）：1
处理中断：0
【未进入处理的计划账号（不计入已开始主状态合计）】
进入处理前异常（不计入主状态合计）：1
未开始（不计入主状态合计）：18
【附加状态（可与主状态重叠，不计入主状态合计）】
完成但有异常记录（附加状态，不计入主状态合计）：2

私密账号（2）：A55、A72
已开始后处理异常（1）：A68
进入处理前异常（1）：A69
未开始（18）：A82-A99
附加状态：异常后完成（2）：A61、A74

原生日志：F:\...\Volume\Log\2026-08-13 10.20.00.log
```

普通的“有新作品下载”“作品均被引擎跳过”“无符合条件作品”默认只显示数量。私密、异常、中断、未开始和异常后完成显示完整 A 编号；连续编号可以压缩为范围，但不得省略账号。

日志定位、读取或校验失败时，信息框应明确显示失败原因，例如：

```text
下载进程：正常退出（退出码 0）
账号结果：无法可靠汇总
原因：无法唯一确定本次原生日志
```

## 9. DownloadTask 日志内容

每个现有的 `DownloadTask_*.log` 追加：

- 进程结束时间和退出码；
- 原生日志绝对路径或路径列表；
- 日志定位依据及读取区间；
- 计划账号、实际开始和各状态数量；
- 私密、异常、中断、未开始和异常后完成的完整 A 编号；
- 完整性与统计校验结果；
- 汇总失败时的明确原因；
- 以下固定状态说明。

```text
【状态说明】
已开始账号主状态：每个实际开始账号只计入一种主状态，六类主状态合计等于实际开始账号数。
有新作品下载：日志最终统计的下载作品数大于 0。
作品均被引擎跳过：筛选后有作品，但视频、图集和实况最终全部计入跳过。
无符合条件作品：筛选处理后的作品数量为 0。
私密账号：出现明确的私密账号提示。
处理异常，需核对（已开始主状态）：账号块中出现无法确认已恢复的错误。
处理中断：账号已经开始处理，但进程结束前未形成可确认的最终结果。
进入处理前异常（不计入已开始主状态合计）：URL/sec_user_id 解析失败而未进入账号处理。
未开始（不计入已开始主状态合计）：仅指本次任务启动时 enable=true 且 URL 有效、但在进程结束前尚未轮到的账号；本次 enable=false 或 URL 为空的账号不参与统计。
完成但有异常记录（附加状态，可与主状态重叠，不计入主状态合计）：出现网络中断或重试，但之后仍产生完整的作品统计。
结果不完整：用户停止、异常退出、日志截断、计划账号未全部完成，或其他证据不足导致无法确认完整任务结果。
```

## 10. 实现边界与调用链

预计新增独立日志汇总模块，由下载运行服务负责：

1. 启动前冻结计划账号映射和日志目录内存快照；
2. 将快照和映射保存在本次 `EngineRun`；
3. 进程结束后由后台工作线程执行日志定位和逐行解析；
4. 将结构化内存结果交给 GUI 格式化并追加任务日志；
5. 汇总回调完成后，队列状态机才进入下一任务。

日志解析器不负责写正式配置，不持有正式文件锁，不访问数据库，不改变下载进程。

## 11. 测试要求

至少覆盖：

- 从 `A50` 开始以及不连续账号的任务内序号映射；
- `enable=false` 和空 URL 不参与计划或未开始统计；
- `mark` 完整精确身份匹配；
- 有新作品下载、全部跳过、筛选为零、私密；
- URL/sec_user_id 解析失败且没有“开始处理”日志；
- 错误后恢复、未恢复错误和处理中断；
- 用户停止、崩溃和非零退出的部分汇总；
- 新建日志和追加已有日志的定位；
- 多候选日志、截断日志、编码异常、序号或身份错位；
- 实际开始按有效唯一序号计算；
- 两级统计公式和附加状态不重复计数；
- 队列等待本次汇总完成再启动下一任务；
- 信息框和任务日志包含完整 A 编号及固定状态说明；
- 不生成目录快照文件、压缩日志、独立 JSON 或原生日志副本；
- 不修改 `settings.json`、`settings_master.json` 的 `enable` 或数据库。

自动测试使用临时目录、合成配置和合成日志。工作区脱敏日志样例只用于只读兼容验证，不进入正式数据路径。
